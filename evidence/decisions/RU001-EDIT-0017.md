# RU001-EDIT-0017 — portable provenance locators

## Question

The assembled Papers 1–43 source still exposed 211 comments rooted at
`interlanguage-workspace://…`. Those comments preserved useful
unit-level provenance, but they were tied to one private workstation and were
unsuitable for a public editable-source package.

## Decision

Replace only the common comment prefix

`% Source: interlanguage-workspace://03_projects/noether/02_slavic_working_corpus/`

with the portable logical prefix

`% Source: noether-corpus://corpus/02_slavic_working_corpus/`.

The scheme root is defined by the edition’s machine index. The remainder of
every source locator is byte-preserved, so paths continue to identify the same
paper, section, language, version, and filename. Eight already-relative
`../producer_units/…` locators remain unchanged.

## Exact scope

- File: `source/base-papers1-43-ru.tex`.
- Changed comment prefixes: 211, from line 33 through line 24741.
- Predecessor: 2,861,872 B / SHA-256
  `DE0621CD3C773B31603CD9BC743DE19BB266B6973A70865F448E1870604593CD`.
- Successor: 2,854,276 B / SHA-256
  `D53F4E0E1D24623B353A562480A53BE8478BB6CB39BBDC36ED0E820D73495B9A`.
- Byte delta: −7,596 B, exactly 211 copies of the prefix-length difference.
- `source/44-book-ru.tex`, `source/45-ru.tex`, and `source/bib-ru.tex` are
  unchanged.

No rendered prose, mathematics, command, environment, citation, label, or
whitespace outside the declared prefixes changed.

## Why this form

The logical URI remains stable if the workspace, repository, archive, or user
directory moves. It also gives machines a single explicit root to resolve
through `machine_index/LANGUAGE_EDITION_INDEX.json`, while retaining the full
fine-grained source trail inside the TeX.

Rejected alternatives:

- deleting the comments, because that would destroy unit-level provenance;
- retaining the private absolute paths, because they are nonportable and leak
  an irrelevant workstation layout;
- replacing every comment with only a paper number, because that would lose
  section, language, version, and witness filenames;
- converting the eight producer locators, because they already resolve within
  the edition tree and express a different, local dependency relation.

## Verification

The applicator’s two read-only projections were byte-identical. An independent
in-memory replacement calculated the same successor identity. Post-apply checks
found zero old prefixes, exactly 211 logical prefixes, zero absolute source
headers, and no transaction residue. Replacing the logical prefix back with the
private predecessor prefix restores the exact EDIT-0016 hash. The four build
sources other than the assembled base remain byte-identical.

This is a provenance-only editorial change. It makes no native-Russian
certification claim, no critical-edition claim, and no claim that the upstream
translation witnesses constitute a native linguistic canon.
